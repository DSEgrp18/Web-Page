# Every Python package in the reader's images, pinned exactly.
#
# Applied with `pip install -c` by infra/api.Dockerfile and infra/tts.Dockerfile.
# A constraints file only pins what is actually installed, so one file serves
# both images: the API image takes the packages it asks for at these versions
# and ignores the rest, and wherever the two images share a package they run
# the same version of it.
#
# Why this exists (#79): the images used to install `>=` floors, which resolve
# to whatever is newest at build time. On 23 September 2026 a rebuild from an
# unchanged commit pulled torch 2.9 and the voice stopped loading. These are
# the versions of an image that is known to work, not a list typed by hand.
#
# Where it came from: `pip freeze` in the voice image (infra/tts.Dockerfile),
# built by CI at commit 1c26156, run 35860729304, by the workflow then named
# voice-image.yml and now .github/workflows/python-images.yml. That image
# holds every package the API image needs as well.
#
# torch and torchaudio keep their `+cpu` labels: those builds come from the
# PyTorch CPU index, and the label is what stops a multi-gigabyte CUDA build
# being chosen instead. The GPU deployment on Modal pins its own torch and is
# not built from this file.
#
# To update: change a version in a Dockerfile, let CI build the voice image,
# and replace the pins below with the `pip freeze` it records. Do not edit a
# single pin by hand unless you have built the images with it.
